## 0. 项目定位

**What I've Learned**：一个由两个 markdown 目录驱动的个人学习记录站。

两个目的：
1. **激励与跟踪自己的学习**——记录"学了什么/要学什么"，用数据与可视化为持续学习提供正反馈；
2. **面试展示项目**——网站本身即作品：架构（markdown → 类型安全数据 → 多视图投影）、可视化（知识图谱）、工程质量（schema 校验/CI/测试/性能预算）都要能讲出权衡故事。

设计要求（用户原话）：**简洁、高技术力而有新意；不要千篇一律的 AI 风格，也不要没有审美的炫技。**

## 1. 调研结论摘要（决策依据）

完整论证见两份调研报告，此处只列直接决定本计划的结论：

1. **「简洁 + 高技术力」的共性是技术力藏在 token 里**（Rauno：全站一条缓动曲线、8px 间距阶梯、单一强调色；Gwern：排版即设计）。约束本身就是风格。
2. **最受好评的知识图谱不是力导向物理图**：roadmap.sh（GitHub 300K+ stars）是编辑手工布局的确定性图；Obsidian 力导向图被社区评为"漂亮但几乎没用"。**帅气来自可控构图 + 语义层（状态编码/hover 子图/点击详情/分级缩放），不是物理模拟。**
3. **时间线的优秀范式是混合的**：叙事流为主体（Maggie 式条目）+ 活动密度热力带（GitHub 式环境级时间线）+ 尺度切换（Histography 的可缩放精神——V1 只取其精神的最小实现，见 §3.1）。
4. **AI 生成网站有可检测指纹**（Inter、蓝紫渐变、玻璃拟态、三列等宽卡……），规避方法是用具体约束替代形容词 + 真内容驱动。配色差异化有数据支撑：**黄棕/琥珀色域几乎无人使用**（Gwern 225 站统计）。
5. **技术主栈**：Astro 7（内容站事实标准，Content Collections + Zod 构建期校验）+ 纯静态输出 + 按需动态加载的交互脚本。
6. **同类项目共性**：构建期解析 → 类型安全数据层 → 静态 HTML + 全量索引 JSON 供交互脚本消费（Quartz 同款路线）。

### 1.1 关键合成决策与风险对策

**图谱 = 确定性聚类布局 + 构建期预计算 + 客户端纯渲染**（不跑物理模拟）。这合并了两份报告的路线：布局由算法在构建期算出（数据驱动、零人工维护），但结果确定性可审阅（roadmap.sh 精神），并规避 Obsidian 图"开场爆炸 + 无语义"两大批评。cross-check 指出该路线的审美前提未经验证、且存在增量稳定性风险，对策：

- **M1 内插入 1–2 天 Atlas spike**（用种子数据出真实 graph.json），以截图评审为通过线；预定义布局失败降级方案（按分类 circle-packing / 半手工坐标覆写文件）；
- **渲染器在 spike 中二选一**：sigma.js v4 beta（声明式样式 + SDF 形状 + 标签事件，官方计划 2026-10 转正）vs **手写 Canvas 2D 渲染器**（零依赖、半填充节点只是两段 arc、本规模 10²–10³ 节点 Canvas 上限 5k–10k 完全够用）。sigma v3 仅作兜底（其自定义 GLSL 在 v4 转正后会作废）。若 M4 启动时 v4 仍未转正且 spike 中暴露阻塞，回落 v3 并记录；
- **增量稳定性写进布局算法验收**：新增一个条目不得移动其他聚类（顶层分类固定角槽 + 聚类内局部摆放）；布局依赖锁版本（lockfile）保证可复现；
- **可审阅形态**：CI 每次构建输出 Atlas 截图（没人 review 坐标 JSON，但人人 review 截图）。

**交互脚本架构 = 零框架运行时 + 按需动态加载**。cross-check 证实 Astro 的 `client:*` 指令只作用于框架组件，"vanilla TS 孤岛"不存在；与其引入 Preact 运行时，不如：图谱/⌘K/筛选全部用 `<script>` + 触发时动态 `import()`（图谱：IntersectionObserver 滚入视口加载；⌘K：首次按键时加载）。这保留了 islands 的性能本质（首屏零交互 JS），叙事反而更强——"零框架运行时 + 按需加载"。

## 2. 内容模型（Markdown 即数据库）

### 2.1 两目录约定

```
content/
├── learned/    # 已学：每个材料一个 md，文件名 = URL slug（建议 ASCII kebab-case，标题可中文）
└── backlog/    # 待学：同上
```

- **核心工作流**：想学 → 在 `backlog/` 建 md；学完 → `git mv content/backlog/x.md content/learned/x.md` + 补 date 与笔记 → push 上线。**"晋升"就是移动一个文件**，这是产品的核心仪式；
- 材料详情统一走 `/m/[slug]` 路由（跨两目录唯一），**晋升不改变 URL**（跨目录重名构建报错）；晋升时可把原 `date`（加入日期）挪到 `added` 保留"等待了多久"这个数据；
- 每个目录一个 `_template.md`（构建排除 `_*`）；
- 笔记正文 = 完整 markdown（GFM、代码高亮）。

### 2.2 Frontmatter Schema（Zod，构建期校验）

```yaml
title: "The Tail at Scale"            # 必填
type: paper                            # 必填，enum（见 2.3）
date: 2026-09-01                       # 必填；learned = 学完日期，backlog = 加入日期
category: [Systems, Distributed]       # 可选，多级分类路径；硬校验（见 2.4）
description: "为什么尾延迟决定用户体验"   # 可选，一句话简介（列表页展示）
url: https://research.google/pubs/...  # 可选，原文链接
tags: [latency, p99, scheduling]      # 可选，横切标签（图谱跨域连线）
duration: 45                           # learned：实际用时（分钟）；首页"总学习时长"口径
est: 120                               # backlog：预计用时（分钟）；待学页估算口径
pages: 12                             # 可选，页数（论文/书籍）
source: "Jeff Dean & Luiz Barroso"    # 可选，作者/讲者/出处
rating: 4                             # 可选，价值评级 1–5
revisit: true                         # 可选，标记"想复习"
why: "面试常问 + 项目要用"              # 可选（backlog 常用），为什么想学
status: learning                      # 仅 backlog：todo | learning（默认 todo）
added: 2026-03-01                      # 可选，原加入日期（从 backlog 晋升时保留）
updated: 2026-09-05                    # 可选，最近修订（笔记持续完善时填写）
draft: true                            # 可选，草稿阀门（不构建、不出现在任何视图）
```

**Schema 工程设计**：
- learned 与 backlog 共享基础 schema，分别扩展（learned: `duration`/`added`/`updated`；backlog: `est`/`why`/`status`），两 collection 定义于 `src/content.config.ts`；
- 非法 frontmatter **构建直接失败**并指向具体文件与字段（CI 天然拦截脏数据）；
- Astro 自动生成 collection JSON Schema → VS Code 写 frontmatter 有补全；
- 软校验（warning 不阻塞）：backlog 条目 `max(date, updated)` 距今超 6 个月且非 learning → 提示"还想学吗"数据。

### 2.3 类型系统（type 枚举，可扩展）

`article 文章 / video 视频 / paper 论文 / blog 博客 / book 书籍 / course 课程 / doc 文档 / talk 演讲 / podcast 播客 / project 项目 / snippet 碎片`

类型不配色（色彩留给状态与强调色），用等宽小字号标签表达——"editorial + technical"。

### 2.4 多级分类：注册表制

- `src/data/categories.ts` 为**唯一真相源**：显式定义分类树（名称、层级、排序——同时决定星图扇区顺序与时间线筛选顺序）；
- frontmatter `category` 硬校验必须命中注册表中的路径——新增分类 = 在注册表加一行（构建错误信息会引导你这么做）。这是"schema as contract"叙事的组成部分，也杜绝拼写错误分裂星系；
- category（学科归属，树）与 tags（跨领域概念，网）职责分离：**category 决定图谱的星系结构，tags 决定跨星系连线**；
- 不用子目录承载分类——保持「往目录里拖一个文件即发布」的极简工作流。

### 2.5 种子内容策略（真实性红线）

学习记录站的价值建立在真实数据上（第一目的），虚构"真实感"内容会污染激励闭环、且在面试追问下是反向暴露。策略：

- 开发期用**少量明确标注的演示条目**（frontmatter `demo: true`，页面可见"示例"角标）驱动视图开发；
- 交付前由用户**回填真实学习史**（8–12 条真实材料胜过 20 条虚构，AI 仅做笔记结构润色、不虚构内容）；
- 空状态/稀疏状态本身就是设计对象（站点初期数据少是真实状态，不是缺陷）。

## 3. 信息架构与页面

| 页面 | 路由 | 一句话 |
|---|---|---|
| 时间线（首页） | `/` | 学习的叙事流 + 活动热力带 + 概览数据 |
| 星图（Atlas） | `/atlas/` | 全量知识图谱：分类为星系、状态为明暗、标签为跨域连线 |
| 待学清单 | `/backlog/` | 想学什么、为什么、以及诚实的"还想学吗" |
| 材料详情 | `/m/[slug]` | 元数据 + 渲染后的笔记正文 + 关联条目（跨目录统一路由） |
| 分类页 | `/category/[...path]/` | 多级分类的文本投影（极简列表） |
| 标签页 | `/tags/[tag]` | 标签聚合列表（近零成本，回答"点标签去哪"） |
| 产物 | `/graph.json` `/search-index.json` `/sitemap-index.xml` `/og/*.png` | 交互数据源与 SEO 门面 |

全局元素：极简导航（站名 + Timeline / Atlas / Backlog + ⌘K 提示）、**⌘K 命令面板**（搜索标题/描述/标签/分类 + 页面直达，键盘可导航）、页脚 colophon（"本站由两个 markdown 目录驱动" + 构建信息——工程师彩蛋）。

### 3.1 首页 · 时间线

```
┌────────────────────────────────────────────────┐
│ What I've Learned        Timeline Atlas Backlog │
│                                                │
│ 站点一句话自述（衬线，编辑感）                      │
│ 42 learned · 118 hours · 6 fields · now: 3      │  ← mono 数据行；now=正在学数量，链到 /backlog
│ [12 个月活动热力带 · hover 显示当日条目]            │
│ [筛选 chips：类型 + 分类，带计数]                  │
│                                                │
│ 2026 ─────────────────────────────             │  ← 年份分隔（锚点跳转）
│ 九月                                            │
│ 09-08 ◦ The Tail at Scale        paper · 45m   │  ← 日期(mono) 状态点 标题(衬线) 类型 用时 标签
│        为什么尾延迟决定用户体验…      [p99]        │
│ …                                              │
└────────────────────────────────────────────────┘
```

- **主体**：纵向叙事流，按「年 → 月」分组倒序；条目行 = 日期（mono）、状态点、标题（衬线）、类型标签、用时/页数、标签；有 description 则弱化随行；
- **热力带**：近 12 个月日活动热力（ink 浓度编码），hover 显示当日学了什么——零成本回答"最近在学吗"；
- **筛选**：类型 + 分类 chips（带计数），触发时动态加载的增强脚本（无 JS 时完整列表可读——渐进增强）；
- **尺度**：年份锚点导航。**明确范围声明：Histography 式连续缩放时间轴不在 V1**（记录为 V2 想法，避免验收预期错位）；
- **动效**：滚动进场轻微 reveal（上移 8px + 淡入，300ms）；首屏阻塞 JS ≤ 5KB。

### 3.2 星图 · Atlas（签名页面）

全站统一纸感浅色——**星图是纸上的墨点星座**（Histography 的中灰底黑点风骨：近乎单色、优雅克制），全浅色方案下的图谱反而更稀有（深底发光图已泛滥，纸面墨点星图几乎无人做）。

**数据与布局**：
- 构建期生成 `/graph.json`：节点 = 分类（树）+ 全部材料（learned + backlog，demo 除外）；边 = 分类从属（实、弱）+ 跨分类标签共现（虚、更弱、可开关）；
- **确定性聚类布局**（构建期预计算，固定随机种子）：顶层分类环形**固定角槽**（角槽序 = 注册表序，与内容量无关——保证增量稳定），子分类嵌套，材料在叶分类附近松弛排布；坐标写入 JSON，每次构建一致（CI 截图供审阅）；
- 客户端渲染器由 M1 spike 决定（sigma v4 beta vs 手写 Canvas 2D，见 §1.1），无物理模拟；入场动画 = 节点从中心散开归位（约 1s，每次访问只播一次，`prefers-reduced-motion` 跳过）。

**语义层**（从 Obsidian 图谱批评中学到的最小必要集）：
- **状态编码**：实心 = 已学、半填 = 在学、空心 = 待学——星图同时回答"我接下来该学什么"；
- **hover**：局部子图点亮、其余淡出 + tooltip（标题/类型/日期）；
- **click**：侧栏详情卡（元数据 + 笔记摘要 + 原文链接 + 查看详情）；
- **语义缩放（LOD）**：远景只见分类标签 → 中景见节点群 → 近景见材料名；
- **节点尺寸**：用时/笔记量的弱编码；
- 图例（状态符号）+ 右上角 mono 统计 +「仅看已学」开关 + 375px 触控调优（tap 容差、捏合缩放）；
- **可访问性声明**：分类页与待学清单页就是图谱的文本投影（页面 `<noscript>` 与 aria 说明中写明）；图谱支持键盘退出（Esc 回收焦点）。

### 3.3 待学清单 · Backlog

- 顶部统计行：`18 waiting · ~64h estimated · oldest 5 months`；
- **「正在学」置顶区**（status: learning，琥珀色点缀）——当前进行时，自我激励的锚点；
- 按**分类分组**：标题 + **why（为什么想学，展示优先级最高的行）** + 类型/预计用时/加入时间；
- **防腐烂**：显示"加入于 n 个月前"；超 6 个月静默（`max(date, updated)`）的条目给一行弱化的"还想学吗？"；
- 完成感：顶部"今年已点亮 n"计数（与星图"点亮"叙事相连）。

### 3.4 材料详情页 · `/m/[slug]`

- 头部：类型标签 + 标题（衬线大字）+ 元数据行（source/date/duration 或 est/pages/rating/原文链接按钮）+ 分类面包屑 + 标签（链到 `/tags/[tag]`）；
- 正文：渲染后的笔记（衬线正文、CJK 优化排版、代码高亮）；`revisit` 给"想复习"徽标；从 backlog 晋升且保留 `added` 时显示"等了 n 个月终于学了"；
- 侧栏（宽屏）：元数据块 + **关联条目**（同分类 / 共享标签 top 3–5）；
- 移动端：单列，元数据折入头部。

### 3.5 分类页 / 标签页（极简）

面包屑 + 计数 + 条目列表 + 子分类列表；标签页 = 同标签条目列表。一个模板族复用。

### 3.6 命令面板 ⌘K

- 触发：⌘K / Ctrl+K（导航栏常驻提示）；**首次按键才动态加载**面板与索引（首屏零成本）；
- 索引：构建期 JSON（材料 + 页面 + 分类 + 标签，< 100KB），minisearch 驱动；
- 键盘全程可操作，分组展示（页面/已学/待学/分类/标签），mono 风格；
- **范围声明：笔记正文全文搜索（Pagefind，v1.5 已内置 CJK 分词）留 V1.1**——V1 面板覆盖"导航与查找"场景；理由：⌘K 的本质是导航面板，全文检索是独立场景，值得单独设计而非塞进面板。

### 3.7 用户路径验证

**访客（面试官/同行）**：落地 3 秒看懂（自述 + 数据行 + 最新条目）→ 滚时间线 → 点条目读笔记 → 进星图把玩 → 看待学页形成对"此人"的判断 → ⌘K 直达。移动端全路径可用。

**主人（作者）**：`git mv` 一个文件即完成晋升；`content/` 目录即全部真相源；星图上看着自己点亮的区域变大（激励闭环）。

## 4. 视觉设计方向

### 4.1 气质关键词

**editorial（编辑感）· calm（克制）· dense（信息密）· handmade（手工感）** —— 用具体 token 兑现，不用形容词空谈。

### 4.2 主题策略（已定：方案 A 全浅色纸感）

全站纸感浅色，**星图为纸面墨点星座**（Histography 式中灰/纸底 + 墨点），无暗色模式、无主题切换——单一主题执行到极致（Gwern：约束本身就够撑起一个可读且美观的网站）。备选 B/C 已在对齐中否决。

### 4.3 Design Tokens（先定约束再动手）

| 维度 | 约束 |
|---|---|
| 色彩 | 纸白底 `#faf8f4` 类暖白 / 暖墨 `#211d17` 类；**唯一强调色：琥珀**（Gwern 数据支持的最空旷色域，契合"点亮"叙事；具体色值实现期以 AA 对比度定稿）；星图 = 纸底 + 墨点（ink 浓度层次替代色相）；状态用**填充度**（实/半/空心）表达而非色相 |
| 字体（≤3 款） | 正文/标题：**Source Serif 4 + 思源宋体**（衬线 editorial 气质）；UI：系统 sans（PingFang/MiSans/Segoe，零加载成本）；元数据/数据：**IBM Plex Mono** |
| CJK 排版 | 中文正文行高 1.75–1.85；行宽以汉字计（约 34–38 字/行，拉丁混排时动态放宽）；中西文混排间距（`text-autospace`/微间距 token）进 token 表 |
| 字体加载 | 思源宋体按频次子集化（cn-font-split 或 fontsource 分包）+ 高频块预载 + `font-display: swap` + 系统衬线兜底；**上线前实测逐块 FOUT 可接受度**（与 Gwern 单文件拉丁字体的无感替换不同，需真实验收） |
| 间距 | 8px 基准阶梯（8/16/24/32/48/64/96…） |
| 圆角 | ≤3 档 |
| 动效 | **全站一条缓动曲线** `cubic-bezier(.2,.8,.2,1)`；UI 微动效 120–240ms；hover/active/focus 三态齐全；`prefers-reduced-motion` 全局支持 |
| 图谱标签语言 | 跟随内容语言（分类名/标题本就是用户手写）；LOD 字号与标签宽度按中英双形态设计（M1 tokens 阶段定稿） |

### 4.4 反 AI 套路 Checklist（上线门禁）

- [ ] 无 Inter 主字体；无 blue/indigo/violet 主色；渐变 ≤1 处
- [ ] 无玻璃拟态导航、无三列等宽卡片阵列、无居中 hero + eyebrow badge
- [ ] 动效全局共用一条缓动曲线；无 `transition-all 300ms ease-in-out`
- [ ] 每个可交互元素 hover/active/focus 三态
- [ ] 图谱关掉动画仍可读可导航；每个效果能回答"它帮我理解了什么"
- [ ] 无 JS 时核心内容可读（时间线/待学/详情/分类）
- [ ] 文案无 "transform/effortlessly/welcome to" 式空话；全站有至少一处"只有这个站才有"的东西（晋升仪式 + 星图状态编码 + 诚实的"还想学吗"）

## 5. 技术架构

### 5.1 主栈

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | **Astro 7 + TypeScript strict**（static 输出，零框架运行时） | 内容站事实标准；Content Collections 原生 Zod 校验；本计划无重量级 Astro 集成依赖，新版本生态风险低 |
| 内容 | 两个 collection（glob loader）+ 共享 Zod schema + `src/data/categories.ts` 注册表 | 构建期校验、自动类型、编辑器补全 |
| 样式 | **Tailwind CSS v4**（`@tailwindcss/vite` **pin ≥ 4.2.2**，官方 Vite 8 支持）+ CSS 变量 tokens | 快速而受控；token 全自定义（不用默认色板）；不在组件 `<style>` 里用 `@apply` |
| 图谱 | **M1 spike 决定**：手写 Canvas 2D 渲染器 或 sigma.js v4 beta（v3 兜底） | 见 §1.1；本规模 Canvas 上限 5k–10k 节点，绰绰有余 |
| 时间线 | 自绘 CSS（grid + scroll reveal） | 无趁手库；自绘保住零 JS 基线，也是高技术力展示位 |
| 搜索 | 构建期 JSON 索引 + minisearch + 自绘 ⌘K 面板（首次按键动态加载） | <100KB、零服务器、风格全控 |
| OG 图 | Satori + Sharp 构建期生成（站名 + 标题 + 类型字） | 分享门面（简历/IM 里链接的卡片） |
| 部署 | **GitHub Pages**（部署简单优先，个人自用；用户已定） | Actions 构建 + Pages 发布，全仓库自包含；roadmap.sh 同款"无聊但可靠"路线 |
| 测试 | Vitest（lib 层）+ Playwright（e2e）+ Lighthouse CI | 见 §7 |

### 5.2 数据流与加载策略

```
content/learned/*.md ─┐
                      ├→ Astro Content Collections（Zod + 注册表校验）
content/backlog/*.md ─┘        │
                               ├→ 静态 HTML：/ · /atlas/ · /backlog/ · /m/[slug] · 分类页 · 标签页 · sitemap
                               ├→ /graph.json（节点+边+预计算坐标，确定性布局）
                               └→ /search-index.json（⌘K 数据源）
```

- **加载策略（零框架运行时）**：所有页面首屏阻塞 JS ≤ 5KB（仅内联监听器与极小运行时）；图谱脚本 IntersectionObserver 滚入视口后动态 `import()`；⌘K 面板首次按键时动态 `import()`；筛选 chips 点击时动态 `import()`；
- 无 JS 降级：时间线/待学/详情/分类全量可读，图谱页显示文本投影说明（指向分类页）；
- 图布局算法收敛于 `src/lib/graph/`（纯函数、可单测、固定种子、锁 lockfile 可复现），渲染层薄接口隔离（spike 二选一后定型）。

### 5.4 工程细节

- pnpm + Node 22；Biome（lint + format）；
- CI：lint → `astro check` + build（schema 校验在此拦截脏数据）→ vitest → Playwright → Lighthouse CI → **Atlas 截图产物**（布局可审阅性）→ 部署 GitHub Pages（`actions/deploy-pages`，官方 withastro/action 模板）；
- **GitHub Pages 细节**：project pages 需配 Astro `base`（用户名仓库 `username.github.io` 则无需）——全站统一走相对路径/base 感知的 URL 工具函数，避免以后换自定义域名时返工；产物体积远低于 Pages 限额；
- 性能预算（写进 README，区分阻塞/延迟）：首屏阻塞 JS ≤ 5KB；图谱延迟包 ≤ 250KB gzip（Canvas 手写则远小于此）；⌘K 延迟包 ≤ 60KB；Lighthouse 性能/无障碍 ≥ 95（星图页 ≥ 90）；构建 < 60s；
- 已知坑规避：Tailwind vite 插件显式 pin（`@latest` 有解析到陈旧 dist-tag 的案例）；OKLCH 被 LightningCSS 改写的边角问题用 `build.cssMinify: 'esbuild'` 兜底；npm 错误提升 Vite 的坑用 pnpm 规避。

## 6. 面试叙事（写进 README 的主线）

1. **Content as Code**：两个 markdown 目录 = 数据库；Zod schema + 分类注册表 = 契约；CI = 数据质量门禁；编辑器补全 = 开发体验设计。
2. **一份数据三个投影**：时间线/星图/待学清单消费同一 collection——架构上回答"为什么首页是时间线而图谱能回答下一步学什么"。
3. **确定性图谱布局**：为什么不用运行时力导向（Obsidian 批评），为什么构建期预计算坐标（可审阅 + 免模拟收敛 + 增量稳定），怎么做到固定种子可复现；渲染器选型是 spike 驱动的决策记录（sigma v4 vs 手写 Canvas，附对比数据）。
4. **零框架运行时 + 按需动态加载**：不用任何前端框架，交互脚本全部按需加载——islands 思想的彻底版；性能预算的量化兑现。
5. **设计系统即约束**：一条缓动曲线、一个强调色、8px 阶梯——以及反 AI 套路 checklist（附调研报告链接）。

## 9. 决策记录（2026-09-08 对齐结果）

1. **主题策略 → A 全浅色纸感**：全站暖白纸底，星图为纸面墨点星座（Histography 式近单色墨点），无暗色模式。
2. **界面语言 → 混合**：导航与结构性词汇用英文（Timeline / Atlas / Backlog），正文自述与内容跟随中文为主的内容语言；图谱标签跟随内容语言。
3. **部署 → GitHub Pages**：部署简单优先、个人自用；Actions 自动构建；base 路径走相对化处理；大陆可达性风险接受（github.io 相对可达），备离线演示兜底。
4. **内容策略 → 真实史回填**：开发期用标注 `demo` 的演示条目；交付前用户回填 8–12 条真实学习史（笔记协作撰写，AI 不虚构内容），演示条目移除后上线。
5. **图谱渲染器 → 手写 Canvas 2D**（2026-09-08 spike 结论，取代 M1 的"二选一待定"）：
   - spike 产出完整可交互实现（`src/components/atlas/renderer.ts`，~500 行零依赖）：视口自适应、入场动画（每会话一次、reduced-motion 跳过）、拖拽/滚轮/双指捏合、hover 自我中心子图点亮、点击侧栏、LOD 标签、cross-links 与 learned-only 开关。
   - 截图评审通过（7 轮迭代）：曼陀罗六扇区构图、靶心=field/菱形=topic/填充度=状态的编码可辨、纸面墨点气质达成。
   - 关键理由：(a) 视觉完全受控——墨色 ramp/发丝线/唯一强调色虚弧需要逐像素控制，sigma 默认渲染要大量逆向定制；(b) 布局是构建期预计算的确定性几何（角槽 + 日期角度），sigma 的运行时布局反而是阻力；(c) sigma v4 仍处 beta（stable 计划 2026-10），v3 的 GLSL 定制在迁移时丢弃；(d) 性能充足（目标规模 ≤500 节点，Canvas 2D 无压力；渲染器 gzip ≈ 8KB，预算 250KB）。
   - 回退路径：若真实数据规模（500+ 节点）出现帧率问题，局部迁移到 sigma v4 stable（graph.json 数据契约不变）。
6. **demo 条目口径（2026-09-08 实施修正）**：demo 条目进图谱与统计（原计划"排除"导致开发期星图不可评审）；口径改为"带'示例'角标展示 + 上线前整体移除"（M7 验收项），简单且诚实。
